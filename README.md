# كامب جذور — نظام المتابعة والتقييم المركزي

لوحة تحكم تشغيلية (Executive Dashboard) لإدارة «كامب جذور» التابع لـ**نوادي صناع الحياة بالجامعات المصرية** — تُبنى من ملف بيانات «الإدارة المركزية لكامب جذور» وتعمل بنسخة البيانات المرفقة، مع إمكانية الربط الحي بجدول Google Sheets عبر Google Apps Script.

---

## الصفحات

| الصفحة | الملف | المحتوى |
|---|---|---|
| النظرة التنفيذية | `index.html` | ملخص KPIs، اتجاه الحضور، الحرارة، محاور التقييم، التاسكات، القياس، حركة الفترات |
| الحضور | `attendance.html` | يومي/مسار/خريطة حرارية + جدول ترتيب الأيام |

| التقرير التنفيذي | `executive-report.html` | وثيقة جاهزة للطباعة/PDF |

## التشغيل المحلي / النشر

### 1) نسخة البيانات المرفقة (الافتراضية)
افتح أي صفحة **بضغطة دبل كليك** مباشرة من المجلد — البيانات مضمّنة في `data/bundled-data.js` فتعمل فورًا حتى دون خادم (متصفحات JavaScript فقط). عند الرفع على GitHub Pages تُقرأ من `data/processed-data.json` تلقائيًا، وبلا إنترنت سوى لمكتبتي ECharts وخطوط Google Fonts.

### 2) الربط الحي بـ Google Sheets (اختياري)
1. أنشئ جدول بيانات Google Sheets بغُرف بنفس أسماء أوراق ملفك الأصلي: `attendence`، `feedback`، `assignment`، `prequiz`، `postquiz`، و`camp_registration` (ملخص سريع في صفحة «ملخص التسجيل»).
2. الصق بيانات كل ورقة من الملف الأصلي بالترتيب نفسه.
3. انسخ محتوى `apps-script/Code.gs` إلى مشروع Apps Script جديد ملحق بالجدول.
4. غيّر `SPREADSHEET_ID` في أعلى الملف إلى معرف جدولك.
5. انشر المشروع كـ **Web App** بتنفيذ `doGet` ووضع «أي شخص»:
   - Run as: **Me**
   - Who has access: **Anyone**
6. في المتصفح ستُنقر الصفحة، ثم في وحدة التحكم شغّل:
   ```
   localStorage.setItem('camp_juzur_url', 'https://script.google.com/macros/s/AKfycbx25e5ryo8npVWUBSUVp0iLEl1dxSCJ9kzLZZB_MD08-vM2c47tF7dJnIRqfJZ64c9u/exec');
   ```
   ثم حدّث الصفحة — ستصبح البيانات حية (تُخزَّن مؤقتًا 30 دقيقة عبر CacheService).
7. للعودة للنسخة المرفقة: أحذف المفتاح `camp_juzur_url` من localStorage.

> عند استضافة اللوحة داخل Apps Script (وضع HTML بداخله) يعمل `google.script.run` تلقائيًا دون إعداد.

## تحديث البيانات المرفقة عند تعديل الملف الأصلي

أعد توليد `data/processed-data.json` من ملف Excel الأصلي عبر الأداة المستخدمة في البناء (برنامج PowerShell يُعيد تصدير كل ورقة بصيغة `{headers, rows}` بالتواريخ كأرقام تسلسلية Excel). يجب بقاء بنية المخطط كما هي:

```json
{
  "meta": { "serialBaseDate": "1899-12-30", ... },
  "sheets": { "attendance": { "headers": [...], "rows": [[...]] } , ... }
}
```

## مبادئ صارمة (وثّقناها في PLAN.md وDATA_DICTIONARY.md)

- **لا افتراض في الأرقام**: كل قيمة غير قابلة للحساب تُعرض `—` أو «غير متاح من البيانات الحالية» مع السبب.
- **لا يُحذف خام**: أبدًا؛ تُعلَّم الصفوف بعلامات تحقق فقط.
- **الخصوصية**: لا تُعرض أرقام قومية / واتساب / إيميلات في الواجهة إطلاقًا؛ تُستخدم للربط الداخلي فقط.
- المقياس: ممتاز=4، جيد جدًا=3، جيد=2، يحتاج تطوير=1.
- القياس القبلي/البعدي لا يُقرأ كدرجات خام بل كنسبة مئوية + المزدوج (Paired) كالمصدر الرئيسي.
